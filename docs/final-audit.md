# HealSpoc Rebuild: Independent-Style Release Audit

**Reviewed:** 2026-11-14. **Repository:** <https://github.com/w3bhub2/HS>. **Public page:** <https://w3bhub2.github.io/HS/>. The separate `healspoc.com` WordPress website was not replaced or secured by this release.

## Evidence actually collected

- Source and public-site reconnaissance are recorded in `docs/audit-findings.md`. Public WordPress content includes unverified/template material, but no privileged security finding or confirmed compromise was established.
- The site builds with Vite and passes strict TypeScript checking. A static audit checks 24 prerendered routes, titles, descriptions, canonicals, Open Graph URLs, internal links, images, font files, Organization JSON-LD, sitemap, and the custom 404 page.
- A Chromium/Playwright audit was run against the public GitHub Pages URL: 24 routes at 390px, 768px, and 1440px (72 combinations) with no reported page errors, failed requests, or horizontal overflow. Mobile navigation, the bottom-right WhatsApp panel, treatment-specific messages, the fixed mobile WhatsApp CTA, and event emission were exercised.
- Axe found no WCAG-tagged issues on four representative mobile pages. Live Lighthouse **mobile lab** results were Performance 99, Accessibility 100, Best Practices 100, and SEO 100. Lab LCP was 1.6 s, TBT 10 ms, and CLS 0.004. These are not field Core Web Vitals or manual WCAG conformance tests.
- A separate mocked Web3Forms test exercised API success and failure, phone normalization, the honeypot, reset behavior, and start/submission/error events. It did not deliver an email or prove that the production form works.
- Public GitHub Pages checks returned 200 for key routes, media, fonts, sitemap, and robots, and 404 for an unknown route. GitHub Pages served the site over HTTPS with HSTS. The HTML includes a CSP meta policy, but GitHub Pages does not apply the repository's Apache/Netlify header rules.
- `npm audit --omit=dev --audit-level=moderate` reported zero known production dependency vulnerabilities at audit time. This is not a security penetration test or proof of a secure WordPress installation.

**Overall assessment: 6.4/10, not 10/10.** The public GitHub Pages rebuild is visually and technically stronger than the observed WordPress template, but the live secondary form is not configured, clinical content lacks qualified review, legal details are unconfirmed, and the old site has not been audited or migrated. None of those can be scored as passing simply because the new pages render.

## Required owner actions

1. Supply a Web3Forms key created for `hello@healspoc.com`, add it as the repository Actions secret `WEB3FORMS_ACCESS_KEY`, allow the Pages origin, and complete a real inbox test.
2. Confirm the legal entity, business address/jurisdiction, privacy controller, retention, and patient assistance capabilities; replace the marked policy drafts.
3. Verify any hospitals, clinicians, partnerships, evidence, and patient stories before publishing them; commission qualified medical review for clinical pages.
4. Review the still-live WordPress installation with hosting/admin access, back it up, and investigate the template/placeholder changes. Export search data and plan the old-domain migration only after these checks.
5. Test WhatsApp app handoff and team response on real phones, manual accessibility on representative devices, and analytics only after the privacy approach is approved.
